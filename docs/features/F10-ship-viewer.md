# F10 Unity 샘플 호선 뷰어

상태: 구현됨. 계약은 `contracts/unity-viewer.md`, 검증 결과는 `docs/handoffs/status.md` 참조.

## 목표와 범위

기존 Vue 호선 상세에서 Unity로 렌더링한 예시 선박 한 척을 조회한다. 실제 호선의 설계 형상을 재현하는 기능이 아니다. 모든 호선에서 같은 샘플을 열 수 있으며 선택한 호선의 실제 형상으로 오인하지 않도록 한다.

- Unity Web(WebGL) 빌드를 사용한다. Three.js 등 다른 엔진으로 임의 대체하지 않는다.
- 외부 모델 없이 선체·갑판·선실로 구성한 단순한 예시 선박을 만든다. 선체는 선수와 선미가 구분되는 간단한 메시로 구성하고, 나머지는 기본 도형을 활용한다.
- 유료 에셋, CAD 변환, 여러 선박 모델 관리, 블록 선택, 실시간 공정 연동, 조립 애니메이션은 이번 범위에서 제외한다.
- DB 테이블과 업무 API 추가는 필요하지 않다. 샘플 기하 데이터는 Unity 내부에서 생성해도 되며 실제 업무 데이터는 기존 API 원칙을 유지한다.

## 화면과 상호작용

- 기존 호선 상세의 서브탭으로 `3D 보기`를 제공한다(사용자 지시로 버튼에서 변경). 모달을 겹치지 않으며, 신규 등록 중에는 표시하지 않는다.
- 3D 탭에서는 모달을 넓혀 큰 뷰어 영역과 작은 정보 영역을 둔다. 제목은 `샘플 호선 3D 뷰어`, 모델명은 `Demo Ship 01`로 표시한다.
- `예시 모델 — 실제 호선 형상과 다름` 안내를 항상 표시한다. 가상의 치수를 실제 제원으로 제시하지 않는다.
- 마우스 왼쪽 드래그: 회전, 휠: 확대·축소, 오른쪽 드래그: 화면 이동. 조작 안내를 표시한다.
- 정면·측면·상단·초기화 버튼을 제공한다. 초기화는 위치·방향·줌 모두 복구한다.
- 확대·축소와 회전 범위를 제한해 카메라가 모델 내부로 들어가거나 모델을 잃지 않게 한다.
- 로딩 진행률, 로딩 실패 메시지, 재시도, 닫기를 제공한다. Unity 준비 전 시점 버튼은 비활성화한다.
- 첫 진입에만 Unity 로더를 불러온다. 닫기·화면 이탈 시 인스턴스와 이벤트를 정리하고, 로딩 중 닫기 및 반복 열기에서도 중복 인스턴스를 만들지 않는다.
- 호선 조회 권한을 따르는 기존 UI 흐름을 유지한다. 공개 정적 빌드에 민감한 정보나 토큰을 포함하지 않는다.

## 구현 배치 (제안)

| 위치 | 역할 |
| --- | --- |
| `unity/ShipyardViewer/` | Unity 프로젝트 원본 |
| `unity/ShipyardViewer/Assets/Scripts/` | 샘플 메시·카메라·브라우저 메시지 처리 |
| `unity/ShipyardViewer/Assets/Editor/` | 씬 생성·Web 빌드 자동화가 필요할 경우 |
| `frontend/public/unity/ship-viewer/` | 실행 가능한 Web 빌드 결과 |
| `frontend/src/components/ShipViewer.vue` | 로더, canvas, 상태, 종료 처리 |
| `frontend/src/screens/hulls/HullDetailModal.vue` | 기존 상세에서 진입 연결 |
| `contracts/unity-viewer.md` | 구현 시 확정한 메시지·빌드 경로·준비 및 종료 규약 |

브라우저에서 C# 호출은 Unity 인스턴스의 `SendMessage`로 연결할 수 있다. 함수명과 데이터 형식은 구현 시 계약 문서에 기록한다. 이 버전에는 인증 토큰 전달이나 Unity의 직접 API 호출이 필요 없다.

## 환경과 빌드

- 설치된 Unity Editor 버전, 해당 버전의 Web Build Support, 라이선스·실행 가능 여부를 먼저 확인한다. 사용할 버전은 `ProjectVersion.txt`에 고정한다.
- Unity가 없으면 C# 작성 가능 범위와 실제 Editor 빌드가 필요한 범위를 구분한다. 설치·라이선스가 필요한 정확한 조치를 사용자에게 안내한다. 코드나 빈 폴더만 만들고 렌더링 완료로 보고하지 않는다.
- 사용 버전의 공식 문서에서 로더 API, 종료 처리, 압축 및 WebAssembly 제공 조건을 확인한다.
- 로컬 검증은 압축을 끈 빌드로 단순화할 수 있다. 배포에서 압축을 켜면 실제 서버의 Content-Encoding 및 Content-Type 설정을 함께 검증한다.
- 빌드 산출물 이름을 추측하지 말고 실제 빌드 설정에서 연결한다. 설치·실행·빌드 명령과 출력 경로를 기록한다.

## 수용 기준

- VIEWER-T01: 기존 호선 조회에서 진입·복귀하며 호선 수정·탭 동작에 회귀가 없다.
- VIEWER-T02: 브라우저에서 실제 Unity 샘플 선박이 표시되고 예시 모델 안내가 보인다.
- VIEWER-T03: 회전·줌·이동과 네 가지 시점 버튼이 정상 작동한다.
- VIEWER-T04: 실패 시 안내·재시도가 가능하고 준비 전 조작이 차단된다.
- VIEWER-T05: 로딩 중 닫기와 반복 열기·닫기에서 늦은 로딩 결과, 중복 canvas, 이벤트 누적 오류가 없다.
- VIEWER-T06: 호선 관련 기존 테스트와 프론트엔드 빌드를 통과한다. 새 검증은 로더 실패·지연 완료·종료 등 실제 회귀 위험에 집중한다.
- VIEWER-T07: 로컬 HTTP 서버에서 실제 Web 빌드를 실행하고 콘솔·네트워크 오류 및 창 크기 변경을 확인한다. 소스 작성·Vue 빌드 성공만으로 Unity 실행 성공을 대신하지 않는다.
