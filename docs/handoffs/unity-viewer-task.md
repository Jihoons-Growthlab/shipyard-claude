# Claude Code 작업 지시: F10 샘플 호선 뷰어

사용자가 F10 구현을 요청했을 때 실행한다. 이 문서 자체가 자동 실행 명령은 아니다.

## 시작 프롬프트

```text
CLAUDE.md, docs/features/F10-ship-viewer.md,
docs/handoffs/unity-viewer-task.md를 읽고 F10을 구현해줘.
샘플 선박 한 척을 Unity Web으로 렌더링하고 기존 호선 상세에 연결해.
아래 단계별 검증을 수행하고, 가능한 작업은 완료까지 진행해.
Unity 설치·라이선스·모델 등 실제로 필요한 외부 준비만 구체적으로 알려줘.
기존 기능과 권한을 유지하고, 실제 실행하지 못한 검증은 미확인으로 보고해.
```

## 1. 필요한 범위만 조사

- F04 명세, 호선 상세와 관련 모달·스타일·테스트·패키지 설정을 읽는다.
- `reference/UiImages/README.md`와 `hull-detail-modal.png`를 직접 열어 기존 화면의 스타일을 확인한다. 제공 이미지에 3D 뷰어 시안이 있다고 가정하지 않는다.
- Unity 환경 및 기존 Unity 프로젝트 유무를 확인한다. 설치되지 않았으면 필요한 Editor·Web 모듈·라이선스 준비를 알리고, 그와 독립적인 소스·설계 작업을 진행한다.
- 현재 작업 파일의 기존 변경을 보존한다. 프로젝트 전체 파일이나 전체 목업을 한 번에 출력하지 않는다.

## 2. 샘플 선박과 Unity 뷰어

- 사용 가능한 Unity 버전으로 최소 프로젝트와 재현 가능한 씬 생성 방식을 준비한다.
- 기본 재질·조명·카메라와 선체·갑판·선실을 구성한다. 카메라 조작과 시점 변경을 구현한다.
- Unity Editor에서 확인 후 실제 Web 빌드를 생성한다. Editor 실행이 불가능하면 해당 검증은 미확인으로 남긴다.

## 3. Vue 연결

- Unity와 Vue 사이 시점 메시지, 로더 준비·실패·종료 규칙을 `contracts/unity-viewer.md`에 간결하게 기록한다.
- 지연 로딩·진행률·에러·재시도·종료 처리를 구현하고 호선 상세에 연결한다.
- 기존 UI 규칙을 재사용한다. 샘플 뷰어를 위해 회원·결재·공정 API를 수정하지 않는다.

## 4. 검증과 인수인계

- F10 수용 기준을 확인하고 관련 테스트 및 프론트엔드 빌드를 실행한다.
- Playwright가 가능하면 실제 웹 화면의 진입·종료·오류를 확인한다. canvas 내부 모델과 시점은 스크린샷으로 직접 비교한다. DOM 검사만으로 렌더링 성공이라고 판단하지 않는다.
- 의미 있는 변경 뒤 캡처하고, 같은 화면을 반복해서 출력하지 않는다. 실패가 남으면 해당 영역에 집중한다.
- `docs/handoffs/status.md`에 변경 파일, Unity 버전, 실행·빌드 방법, 검증 결과, 미해결 사항을 기록한다. 문서 작성과 실제 구현 완료를 구분한다.

## 토큰 관리

- `Library/`, `Temp/`, `Obj/`, `Logs/`, 빌드 바이너리, 외부 패키지 전체를 기본 읽기 대상에서 제외한다. 필요한 C#·Vue·계약과 오류 구간만 읽는다.
- `Assets/`, `Packages/manifest.json`, `Packages/packages-lock.json`, `ProjectSettings/` 및 `.meta`는 재현에 필요한 원본이다. 전부 차단하지 말고 필요한 파일만 조회한다.
- 단순 CSS 수정에는 문서 검색을 생략한다. Unity 버전에 따른 API가 불확실할 때만 공식 문서나 Context7을 조회한다.
- `/context`는 단계 경계에서 사용량 확인에 활용한다. 같은 문제를 이어갈 때 필요하면 `/compact`를 쓰되 결정·남은 작업·실패 원인을 보존한다.
- `/clear`는 자동으로 실행하지 않는다. 독립적인 다음 단계로 전환할 때 인수인계 기록 후 사용자가 선택한다. 매번 초기화해 관련 코드를 다시 읽는 패턴은 피한다.
- 토큰 실험에서는 준비 문서·검색·수정·검증·재시도 비용을 모두 기록하고, 캐시 토큰과 일반 입력을 구분한다.
