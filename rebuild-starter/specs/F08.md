# F08 결재함

이미지: approvals. 권한: 조회 M33 View, 승인·반려 M33 Write + 지정 결재자. 배포는 F07 API(M31 Write). 규칙 BR-06.

## API

| 요청 | 응답 |
| --- | --- |
| `GET /api/approvals/inbox` | `{waiting:[{approval_id,drawing_id,drawing_no,drawing_nm,rev_no,step_no,change_desc}],ready:[{drawing_id,drawing_no,drawing_nm,rev_no,effect_plans:[라벨]}],can_issue}` |
| `POST /api/approvals/{id}/decision` | `{result:"APPROVE"\|"REJECT",comment}` → `{approval_id,result,waiting,ready}` |
| `GET /api/approvals/history` | 최근 10건 `[{approval_id,act_dt,drawing_id,drawing_no,rev_no,step_no,approver_emp_no,approver_nm,result,comment}]` |

## 규칙

- 대기 조건: 본인 지정, WAIT, Rev가 REVIEW이자 최신, 앞 단계가 모두 APPROVE. ApprovalId순.
- 배포 대기: 최신 Rev가 APPROVED인 모든 도면. `effect_plans`는 연계 공정 중 PLAN 상태.
- `can_issue`는 M31 Write 여부이며 화면 표시용이다.
- 이력은 전체 사용자 대상, Result≠WAIT, ActDt 내림차순·ApprovalId 내림차순.
- 처리 순서: result 값 400(`결재 결과는 APPROVE 또는 REJECT 이어야 합니다.`) → 반려 의견 400(`반려 시 의견을 입력하세요.`) → 404 APPROVAL_NOT_FOUND → 403 NOT_ASSIGNED_APPROVER(`본인에게 지정된 결재 건이 아닙니다.`) → 409 ALREADY_DECIDED(`이미 처리된 결재 건입니다.`) → 409 NOT_CURRENT_STEP(`결재 순서가 아니거나 최신 검토중 리비전이 아닙니다.`).
- 승인 의견이 비면 `승인`. `ActDt`는 `{기준일} HH:MM`(현재 시각).
- 처리 후 BR-06, BR-03.

## 화면

- 제목 `도면 결재함`, 설명 `{이름} 님의 결재 대기와 배포 대기 도면입니다.`
- **내 결재 대기** 카드, b-warn 건수: 도면번호(링크 → 상세 모달), 도면명, Rev, 단계(검토/승인), 변경사유, 의견 입력(`의견 (반려 시 필수)`), 승인(btn ok)·반려. 조회 전용은 버튼 없음. 빈 경우 `결재 대기 건이 없습니다.`
- **배포 대기 (승인 완료)** 카드, b-info 건수: 도면번호, 도면명, Rev, `배포 시 착수 가능해질 수 있는 공정`(쉼표, 없으면 `-`), `배포`(can_issue일 때). 빈 경우 `배포 대기 도면이 없습니다.`
- **최근 결재 이력** 카드: 일시, 도면번호, Rev, 단계, 결재자, 결과 배지, 의견. 빈 경우 `결재 이력이 없습니다.`
- 반려는 의견이 비면 클라이언트에서도 막는다. 처리 중 버튼 비활성, 실패해도 다시 불러온다.
- 토스트: `승인했습니다.`, `반려했습니다. 도면은 작성중으로 되돌려집니다.`, `도면이 배포되었습니다. 연계 공정 상태가 갱신됩니다.`

## 수용 기준

APV-T01 1단계 전 2단계 대기 없음. T02 지정 외 사용자 거절. T03 반려 의견 필수, DRAFT 복귀, WAIT 제거, 반려 이력 유지. T04 양 단계 승인 → APPROVED. T05 배포 후 상태 갱신. T06 최근 10건, 빈 메시지.
