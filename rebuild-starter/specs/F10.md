# F10 샘플 호선 3D 뷰어

이미지: hull-3d, ship-side, ship-front, ship-top. 실제 호선 형상이 아니다. 모든 호선에서 같은 샘플을 연다. DB·업무 API·토큰 전달이 없다. Three.js 등으로 대체하지 않는다.

## 환경

- Unity 6000.5.10f1 + Web Build Support. macOS에서 검증된 경로는 `/Applications/Unity/Hub/Editor/<ver>/Unity.app/Contents/MacOS/Unity`, 모듈은 `<ver>/PlaybackEngines/WebGLSupport`.
- 먼저 Hub 설치 폴더에서 이 모듈이 있는 Editor를 찾는다. 다른 6000.x면 그 버전으로 진행하고 `PROGRESS.md`에 기록한다.
- 라이선스는 `-createProject` 배치 실행으로 확인한다.
- 없거나 실패하면 다른 단계를 끝낸 뒤 멈추고 안내한다: Unity Hub 설치 → 로그인 및 Personal 라이선스 활성화 → Installs에서 해당 Editor + Web Build Support 추가. C#만 작성하고 렌더링 완료로 보고하지 않는다. 호선 상세의 3D 탭은 빌드가 없으면 오류 화면을 보여야 한다.
- 다른 프로젝트를 연 Editor가 있어도 건드리지 않는다. 같은 프로젝트를 Editor로 열어 둔 상태에서는 배치 빌드가 실패한다.

## Unity 프로젝트 `unity/ShipyardViewer/`

- Built-in 렌더 파이프라인, 기존 입력(`Input`). manifest는 imageconversion, imgui, jsonserialize, ui, uielements 모듈이면 충분하다.
- Editor 스크립트 하나가 씬과 재질을 매번 재생성하고 Web 빌드까지 수행한다. `-batchmode -quit -buildTarget WebGL -executeMethod`로 실행한다.

빌드 설정: companyName SWP, productName ShipyardViewer, Linear, runInBackground, 압축 Disabled, decompressionFallback off, nameFilesAsHashes off, dataCaching off, exceptionSupport None, 템플릿 Minimal, stripEngineCode, 관리 코드 스트리핑 High, 그래픽 API는 OpenGLES3만.

출력: `frontend/public/unity/ship-viewer/Build/`. 빌드 후 `index.html`, `TemplateData`를 지우고 실제 파일명으로 `build.json`을 생성한다: `loaderUrl,dataUrl,frameworkUrl,codeUrl`(Build 기준 상대), `companyName,productName,productVersion`. 완성본 빌드 크기는 약 15MB다.

씬:

- 카메라: SolidColor #DDE4EE, FOV 30, near 1, far 1000.
- 태양 Directional, intensity .95, Soft 그림자, 회전 (52,-35,0).
- 앰비언트 Trilight: sky (.42,.47,.54), equator (.34,.37,.41), ground (.24,.26,.29).
- 재질은 Standard 에셋으로 만들어 셰이더 변형이 빌드에 남게 한다.

## 모델 Demo Ship 01

메시는 런타임에 코드로 만든다. 선수 +Z, 지면 y=0. 전장 60, 폭 10, 깊이 6, 킬 높이 .8, 흘수 분할 2.6, 선수 경사 3.

- 스테이션 72개. 높이 행 0, .2, .5, .9, 1.3, 1.6, 2.1, 2.6, 3.2, 4, 5, 5.6, 6. 2.6 아래는 HullLower, 위는 HullUpper.
- 반폭 = 폭/2 × section × plan
  - section = 1 - .55·(1 - clamp01(h/1.6))³
  - zs = z - 3·(h/6). zs>12이면 plan = 1 - clamp01((zs-12)/15)^2.2
  - z<-18이면 s = clamp01((-18-z)/12), plan ×= 1-.28s², section ×= clamp01((h+.15)/6)^(.7s)
- 좌우 현은 곡면 법선을 위해 정점을 병합하되 **현별로 분리**한다. x=0에서 공유하면 법선이 0이 되어 선수가 검게 깨진다. 바닥·갑판·선미판은 각지게 둔다.
- 면 방향은 바깥 방향 힌트로 정한다. 0 면적 면은 건너뛴다.
- 나머지는 상자: 3단 선실(z≈-20, 갑판 위), 브리지 윙, 창, 오렌지 굴뚝(z=-25), 마스트, 해치 4개(z=-9.5부터 8.2 간격, 오렌지 코밍 + 강재 덮개), 카고 포스트 3개, 지면 800×800, 킬 블록 9개.

## 카메라

궤도 카메라. 입력은 목표값을 바꾸고 현재값이 지수 감쇠(k=12)로 따라간다.

- 왼쪽 드래그: yaw .3°/px, pitch .25°/px. 오른쪽 드래그: 카메라 평면 이동(픽셀당 거리 비례). 휠: 거리 ×exp(-wheel·.12), 프레임당 ±3 제한.
- 범위: pitch 4~88, 거리 50~260, 피벗 x±10, y 2~14, z±14. 이 범위 안에서 카메라는 모델에 들어가지 않고 지면 아래로 가지 않는다.
- 기본 피벗 (0,7,0). 시점은 피벗을 기본으로 되돌린다.

| 시점 | yaw | pitch | 맞춤 반폭·반높이 |
| --- | --- | --- | --- |
| reset(초기) | -130 | 20 | 34, 15 |
| front | 180 | 6 | 10, 15 |
| side | -90 | 6 | 33, 15 |
| top | -90 | 88 | 33, 10 |

거리 = max(w/(tan(fov/2)·aspect), h/tan(fov/2)) × 1.15, 범위로 제한. yaw는 짧은 방향으로 돈다. reset은 위치·방향·줌을 모두 복구한다.

그림자: 실행 시 `QualitySettings.shadows=All`, `shadowDistance=400`. 기본 거리로는 궤도 거리에서 그림자가 사라진다.

## 브라우저 계약

- GameObject 이름 `ShipViewer`, 메서드 `SetView(string)`: front/side/top/reset. `instance.SendMessage('ShipViewer','SetView',view)`.
- `.jslib` `ShipViewer_NotifyReady`: `Module.canvas`에 `shipviewer-ready` CustomEvent를 보낸다. 첫 프레임 렌더 뒤 1회.
- `WebGLInput.captureAllKeyboardInput=false`. 그래야 Esc와 폼 입력이 페이지에 남는다.

수명주기(프론트 전용 모듈 하나):

- `build.json`을 `cache:'no-store'`로 받는다. 응답이 JSON이 아니면 SPA 폴백으로 보고 `3D 뷰어 빌드를 찾을 수 없습니다.`
- 로더 스크립트는 첫 진입에 한 번만 불러온다. 실패 시 태그를 지워 재시도를 허용한다.
- **canvas에는 id가 필수다.** Unity가 `'#'+canvas.id`로 찾는다. 없으면 시작 실패.
- `createUnityInstance(canvas,{dataUrl,frameworkUrl,codeUrl,companyName,productName,productVersion,devicePixelRatio:min(dpr,2),showBanner},onProgress)`. `showBanner(msg,type)`는 공식 매뉴얼에 없고 6000.5 로더 코드에서 확인했다. 버전이 다르면 다시 확인한다. type=error면 실패 처리.
- 인스턴스는 동시에 하나다. 새 시작은 이전의 로딩 종료와 `Quit()`까지 기다린다. 로딩 중 닫으면 늦게 온 인스턴스를 바로 `Quit()`한다.
- 종료 후 `WEBGL_lose_context`로 컨텍스트를 해제한다.
- 재시도는 새 canvas를 쓴다(`:key` 증가). 인스턴스 생성 후 준비 신호가 20초 안에 없으면 `3D 뷰어가 응답하지 않습니다.`
- 준비 = 인스턴스 + 준비 신호 둘 다. 그전에는 시점 버튼 비활성.
- 오류 문구는 첫 줄만 표시한다(스택 제외).
- 컴포넌트가 언마운트되면 위 종료를 수행한다.

## 화면

호선 상세의 서브탭 `3D 보기`(F04). 신규에는 없다. 탭에 들어갈 때 시작하고 탭이나 모달을 떠나면 종료한다. 모달이 하나뿐이므로 Esc는 상세를 닫는다. 호선 조회 권한이면 조회 전용도 볼 수 있다.

- 격자 `1fr 260px`, gap 12. 760px 이하 세로(뷰어 min 260px, 정보 max 40vh).
- 뷰어: 테두리, radius 8, 배경 #dde4ee, canvas 전체, 우클릭 메뉴 차단.
- 로딩 덮개: `3D 뷰어 불러오는 중…` + 진척 바. 실패 덮개: `3D 뷰어를 불러오지 못했습니다.`, 사유, `재시도`.
- 오른쪽 카드 3개
  - `샘플 호선 3D 뷰어`: `Demo Ship 01`(15px 700), warn 박스 `예시 모델 — 실제 호선 형상과 다름`. 가상 치수를 표시하지 않는다.
  - `시점`: 정면, 측면, 상단, 초기화(2열).
  - `조작 안내`: 왼쪽 드래그 회전, 휠 확대·축소, 오른쪽 드래그 화면 이동.

## 수용 기준

VIEWER-T01 상세 탭 진입·복귀, 호선 수정·탭 회귀 없음, 3D 탭 왕복 시 작성 내용 유지. T02 실제 canvas에 선박 렌더링을 스크린샷으로 확인, 안내 표시. T03 회전·줌·이동·네 시점, 전 조작 후 reset이 초기 화면과 일치(픽셀 비교), 범위 한계에서 모델 유지. T04 build.json 없음·wasm 실패 시 안내, 준비 전 버튼 비활성, 재시도 복구. T05 로딩 중 이탈·즉시 재진입, 8회 반복에서 canvas·리스너 누적 없음. T06 호선 기존 테스트·프론트 빌드 통과, 로더 실패·지연 완료·종료 테스트. T07 Vite dev와 preview에서 실행, `.wasm`=application/wasm, 창 크기 변경 추종.

종료 시 콘솔에 나오는 WebGL 경고 5건(`bindFramebuffer: invalid target` 등)은 Unity 종료 과정의 것으로 재진입에 영향이 없다. canvas 렌더링을 DOM 값만으로 판단하지 않는다.
