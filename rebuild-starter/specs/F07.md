# F07 도면

이미지: drawing-list, drawing-new, drawing-detail, drawing-detail-draft. 권한: 조회 M31 View, 편집·리비전·결재 요청·배포·연계 M31 Write. 규칙 BR-02, 06~08.

## API

| 요청 | 비고 |
| --- | --- |
| `GET /api/drawings?hull_no&discipline&status&q` | DrawingId순. q는 번호+이름 포함 검색 |
| `POST /api/drawings` | 201, 상세 반환 |
| `GET·PATCH·DELETE /api/drawings/{id}` | DELETE 204 |
| `GET·POST /api/drawings/{id}/revisions` | POST `{change_desc}` 201 |
| `POST /api/drawings/{id}/revisions/{rev}/pdf?filename=` | raw body 업로드, Content-Type은 파일 형식 |
| `GET·DELETE /api/drawings/{id}/revisions/{rev}/pdf` | GET은 inline, `X-Content-Type-Options: nosniff` |
| `POST .../revisions/{rev}/request-approval` | `{reviewer_emp_no,approver_emp_no}` |
| `POST .../revisions/{rev}/issue` | |
| `GET·POST /api/drawings/{id}/plans` | POST `{plan_id,required}` 201 |
| `DELETE /api/drawings/{id}/plans/{plan_id}` | |

목록 항목: drawing_id, drawing_no, drawing_nm, hull_no, block_id, block_cd, discipline, dwg_status, current_rev_no, latest_rev_no, designer_emp_no, designer_nm, link_count.

상세: 위 필드 + block_nm, create_*, modify_*, today, `revisions`(RevNo 내림차순: rev_no, rev_status, change_desc, has_file, file_nm, author_emp_no, author_nm, issue_dt, create_dt), `approvals`(Rev 내림차순, 단계순: approval_id, rev_no, step_no, approver_emp_no, approver_nm, result, comment, act_dt), `plans`(plan_id, label, plan_status, required, need_dt, plan_start_dt, plan_end_dt), `available_plans`, `impacts`(BR-07).

## 규칙

- 생성: `도면번호를 입력하세요.`, `호선을 선택하세요.`, `도면명을 입력하세요.`, `허용되지 않는 분야입니다.`, `해당 호선의 블록이 아닙니다.`, `승인된 회원만 지정할 수 있습니다.`, 중복 409 `이미 존재하는 도면번호입니다.`
- 수정: 이름·분야·블록·설계자만. `호선은 변경할 수 없습니다.`, `도면번호는 변경할 수 없습니다.`
- 상태 충돌은 409 `INVALID_REV_STATE`: `최신 리비전이 배포/폐기 상태일 때만 신규 리비전을 작성할 수 있습니다.`, `최신 작성중(DRAFT) 리비전만 결재 요청할 수 있습니다.`, `승인(APPROVED)된 리비전만 배포할 수 있습니다.`, `작성중(DRAFT) 리비전만 업로드할 수 있습니다.`, `작성중(DRAFT) 리비전만 파일을 삭제할 수 있습니다.`
- 미완료 결재 배포는 409 `APPROVAL_INCOMPLETE` `결재가 완료된 리비전만 배포할 수 있습니다.`
- 신규 Rev 사유 필수 `개정 사유를 입력하세요.` 결재: `검토자와 승인자를 선택하세요.`, `검토자와 승인자는 서로 다른 사람이어야 합니다.`
- PDF: 파일명 정리(경로 제거, 200자), 확장자 `.pdf` 또는 MIME `application/pdf`, 시작 바이트 `%PDF-`, 30MiB 이하(스트리밍 중 초과 시 중단). 오류 400 `INVALID_FILE_TYPE` `PDF 파일만 업로드할 수 있습니다.`, 413 `FILE_TOO_LARGE` `파일 크기는 30MB 이하여야 합니다.` 권한 검사를 본문 읽기보다 먼저 한다.
- 저장: `FileId`는 서버 생성 32hex, 파일은 `{FileId}.pdf`, `FileNm`은 원본 이름. 경로를 받지 않는다.
- 시드의 `FileNm`은 있으나 `FileId`가 없다. `has_file=false`다.
- GET pdf: 파일 없으면 404 `NO_FILE`. 디스크에 없으면 404 `FILE_NOT_FOUND`.

## 목록 화면

- 설명 `행 더블클릭 또는 [상세]로 도면 상세·PDF 뷰어·리비전·결재 팝업을 엽니다. Rev는 현재 배포(유효) 리비전입니다.`
- 필터: 호선 전체(`번호 이름`), 분야 전체, 상태 전체, `도면번호/도면명`(Enter 조회), 조회, 초기화, 오른쪽 `+ 도면 등록`(쓰기). param 호선이 있으면 필터로 적용하고, 재이동 시 다시 적용한다.
- 표: 도면번호(굵게), 도면명, 호선, 블록, 분야, Rev, 상태 배지, 설계자, 연계공정(숫자, 0은 `-`), 상세. Rev는 `Rev{current}`, 최신과 다르면 muted ` (최신 Rev{latest})`. 아래 `총 N건`.

## 신규 모달

제목 `도면 등록`, large. 설명 `신규 도면은 Rev0(작성중)으로 생성됩니다. PDF는 지금 첨부하거나 등록 후 뷰어에서 업로드할 수 있습니다.` 2열 폼: 도면번호 *, 분야 / 도면명 *(2) / 호선, 블록 / 설계자(2, 기본 로그인 사용자) / 도면 파일 (PDF, 선택)(2) / 저장. 호선 기본은 첫 호선, 변경 시 블록 초기화.

클라이언트도 PDF를 검사한다. 생성 후 Rev0에 업로드하고, 토스트 `도면이 등록되었습니다. (Rev0 작성중)` + ` PDF 첨부됨.` 또는 ` (PDF 저장 실패: 사유)`. 그다음 상세로 전환.

## 상세 모달

제목 `도면 {번호}`, xl. 본문 격자 `1fr 440px`, gap 12, 1100px 이하 세로 배치(뷰어 60vh).

**뷰어 카드**(높이 채움): h3 `도면 뷰어 (PDF)` + 오른쪽 12px muted `작성중(DRAFT) 리비전만 업로드·교체·삭제할 수 있습니다.`

- 도구줄: Rev select(`Rev2 (배포)`), 파일명(없으면 `파일 없음`), 배지 `업로드 파일`(b-ok) 또는 `샘플 PDF (미업로드)`(b-warn), 공백, 파일 입력(폭 230, 쓰기 권한자만 표시, DRAFT 아니면 disabled), `파일 삭제`(쓰기, DRAFT + 파일 있을 때만), `새 창으로 열기`.
- 본문 배경 #525659. 파일 있으면 인증 fetch로 blob을 받아 iframe `#view=FitH`. blob URL은 해제한다. 없으면 안내 박스: `샘플 PDF (미업로드)` / `{번호} · Rev{n} · {상태}` / `이 리비전에는 업로드된 도면 파일이 없습니다.`
- 새 창: blob 없으면 토스트 `표시 중인 PDF가 없습니다.`

**오른쪽 열**(스크롤): 상단 12px muted `{호선} · {분야} · {도면명}`.

- 도면 정보 카드: 신규와 같은 폼, 도면번호 readonly, 호선 disabled, 저장·삭제(쓰기). 삭제 확인 `도면과 리비전·결재·공정 연계를 삭제합니다.`
- 리비전 이력 카드: 제목 + 건수 배지. 표 고정폭 92/62/auto/92: Rev(굵게) + `보기` 링크, 상태 배지, 변경사유 + 아래 11.5px 파일명(한 줄 말줄임, title. 없으면 `파일 없음`, 미업로드면 ` (미업로드)`), 배포일(`미배포`) + 아래 작성자. 표시 중인 Rev는 선택색. 표 최대 190px 스크롤.
- 그 아래 작업(쓰기 권한, 최신 Rev 기준):
  - ISSUED/OBSOLETE: `신규 Rev{n} 개정 사유`, 파일(선택), `신규 Rev 작성`
  - DRAFT: warn `Rev{n} 작성중입니다. 검토자/승인자를 지정해 결재를 요청하세요.`, 1단계 검토자(기본 lee.dwg), 2단계 승인자(기본 admin), `결재 요청`
  - REVIEW: warn `Rev{n} 결재 진행중입니다. 결재자는 [결재함]에서 처리합니다.`
  - APPROVED: ok `Rev{n} 승인 완료 — 배포하면 연계 공정의 도면 게이트가 열립니다.`, `Rev{n} 배포`(btn ok)
- 결재 이력 카드: Rev, 단계(검토/승인), 결재자, 결과 배지(대기 warn, 승인 ok, 반려 bad). 행 title에 의견·일시. 빈 경우 `결재 이력이 없습니다.`
- 연계 공정 카드: 제목 + 건수. 영향 있으면 warn `⚠ 최근 개정(Rev{n}, {일자})으로 이미 착수·완료된 공정 {N}건이 영향을 받습니다: {라벨들}`. 표: 공정(링크 → 그 호선 간트, 모달 닫힘), 상태 배지, 필수/참고, 필요일, 해제. 빈 경우 `연계된 공정이 없습니다.` 아래 공정 선택, `필수`(기본), `+ 공정 연계`.

토스트: `저장되었습니다.`, `삭제되었습니다.`, `Rev{n}에 PDF를 업로드했습니다.`, `파일을 삭제했습니다.`, `Rev{n} 작성중으로 생성되었습니다.`, `결재가 요청되었습니다.`, `도면이 배포되었습니다. 연계 공정 상태가 갱신됩니다.`, `공정이 연계되었습니다.`, `연계가 해제되었습니다.`, `공정을 선택하세요.`

조회 전용은 쓰기 요소를 렌더하지 않는다.

## 수용 기준

DWG-T01 필터, Current/최신 Rev 표기. T02 필수·중복, Rev0 DRAFT. T03 다른 호선 블록 거절, 호선 변경 불가. T04 비PDF·30MiB 초과 거절, DRAFT만 파일 변경(UI도 DRAFT만 활성). T05 파일 없으면 샘플 명시. T06 Rev 작성 → 결재 → 배포, 이전 ISSUED OBSOLETE. T07 배포 후 CurrentRevNo·게이트 갱신. T08 연계·영향 경고. T09 삭제 후 고아 없음. T10 VIEW 업로드·배포·삭제 403, 쓰기 UI 없음.
