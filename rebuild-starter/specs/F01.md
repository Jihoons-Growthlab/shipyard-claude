# F01 인증

이미지: login, login-error, signup, otp, login-mobile. 자산: `reference/ui/assets/auth-scene.svg`.

## API

| 요청 | 응답 |
| --- | --- |
| `POST /api/auth/login` `{emp_no,password}` | 일반: `{otp_required:false,access_token,token_type:"bearer",expires_in,user}`. OTP 계정: `{otp_required:true,otp_token,expires_in}` |
| `POST /api/auth/otp/verify` `{code}`, Bearer otp_token | 로그인과 같은 세션 응답 |
| `POST /api/auth/register` | 201 `{emp_no,status:"pending",message}` |
| `POST /api/auth/logout` | 204 |
| `GET /api/auth/me` | `{emp_no,display_name,email,status,totp_enabled,groups:[{code,name}],today}` |

## 규칙

- 비밀번호는 Argon2id. JWT는 HS256, `sub, stage(full|otp), iat, exp, jti`, 세션 토큰은 `lid`(접근 로그 ID) 포함. refresh 없음.
- 로그인: 계정 없음·비밀번호 불일치는 모두 401 `INVALID_CREDENTIALS` `아이디 또는 비밀번호가 올바르지 않습니다.` 비밀번호가 맞으면 상태를 확인한다.

| 상태 | 403 code | message |
| --- | --- | --- |
| pending | ACCOUNT_PENDING | 관리자 승인 대기 중인 계정입니다. |
| rejected | ACCOUNT_REJECTED | 가입이 반려된 계정입니다. |
| disabled | ACCOUNT_DISABLED | 사용이 중지된 계정입니다. |

- 세션 시작 시 `TB_SYS_LogAccess`에 추가(UserId, LoginDt UTC, IpAddress). 로그아웃은 `LogoutDt`를 기록하며, 이후 그 토큰은 401이다.
- 모든 보호 API는 stage=full, 열린 접근 로그, 일치하는 사용자, status=approved를 확인한다. 아니면 401 `세션이 만료되었거나 유효하지 않습니다.`
- OTP: RFC 6238, SHA1, 6자리, 30초, ±1 step. 같은 사용자의 이미 쓴 step은 거절한다. 틀리면 400 `OTP_INVALID` `인증 코드가 올바르지 않습니다.` 토큰당 5회 실패 후 429 `OTP_LOCKED` `인증 시도 횟수를 초과했습니다. 다시 로그인하세요.` 실패 카운터는 프로세스 메모리로 충분하다. OTP 토큰은 보호 API에 쓸 수 없다.

## 가입 검증 (회원관리와 공유)

순서대로 검사하고 400 `VALIDATION_ERROR`, `details.field`로 응답한다.

| field | 조건 | message |
| --- | --- | --- |
| name | 성·이름 필수 | 성과 이름을 입력하세요. |
| birth_date | `YYYY-MM-DD` | 생년월일을 입력하세요. |
| email | `^[^\s@]+@[^\s@]+\.[^\s@]+$` | 이메일 형식이 올바르지 않습니다. |
| phone | `^01\d-?\d{3,4}-?\d{4}$` | 전화번호 형식(010-0000-0000)이 올바르지 않습니다. |
| emp_no | `^[A-Za-z0-9._-]{4,20}$` | 아이디는 영문/숫자/._- 조합 4~20자입니다. |
| password | 8자 이상 | 비밀번호는 8자 이상 입력하세요. |
| password_confirm | 일치 | 비밀번호 확인이 일치하지 않습니다. |

중복은 409 `DUPLICATE`: 아이디 `이미 사용 중인 아이디입니다.`, 이메일(대소문자 무시) `이미 등록된 이메일입니다.`, 전화(숫자 비교) `이미 등록된 전화번호입니다.`

가입 시 `id='u-'+emp_no`, `display_name=성+이름`, 전화는 하이픈 형식으로 정규화, status=pending, `created_at=기준일`, 그룹 없음.

## 화면

- 라우트 `/login`, `/`. 토큰 없으면 `/login`, 토큰 있으면 `/login`에서 `/`로 이동. 토큰은 sessionStorage `swp_token`.
- API 401(토큰 사용 중)이면 세션을 지우고 `/login`으로 이동한다.
- 레이아웃: 전체 화면 `#060f22` 위에 scene을 절대 배치(`preserveAspectRatio` slice, 이벤트 무시). 왼쪽 소개, 오른쪽 카드의 2열, 세로 가운데, padding `40px clamp(28px,7vw,120px)`, gap 48px.
- 왼쪽 소개(z-index 위): `⚓ SWP SHIPYARD`(13px 700, 자간 3px, #8cc1f2), `설계부터 인도까지,<br>조선소 운영을 한곳에서`(`clamp(28px,3.1vw,42px)` 700 흰색), 목록 3행: 호선/호선별 진척률과 인도 일정을 한눈에, 공정/간트 계획부터 일별 실적까지, 도면/리비전·결재·배포 이력 관리. 소개 뒤에 타원형 어두운 그라데이션을 깔고, 소개 블록은 `margin-bottom:22vh`로 위로 올린다.
- 카드: 흰색, 폭 400px(가입 560px), radius 14px, padding 32px 32px 28px, 큰 그림자. 입력 38px, 주 버튼 전체 폭 42px.
- 카드 머리: 로고 12px 700 자간 2px pri, h1 22px navy, 부제 muted.

| 화면 | 로고 | h1 | 부제 |
| --- | --- | --- | --- |
| 로그인 | SWP SHIPYARD | 조선소 통합관리 | 호선 · 공정 · 도면 관리 시스템 |
| OTP | 2-STEP VERIFICATION | 구글 2차 인증 | Google Authenticator 앱에 표시된 6자리 코드를 입력하세요. |
| 가입 | SIGN UP | 회원가입 | 가입 후 관리자 승인이 완료되면 로그인할 수 있습니다. |

- 로그인 하단: 왼쪽 `회원가입` 링크, 오른쪽 `구글 2차 인증 사용 계정은 다음 단계에서 OTP 입력`. OTP·가입 하단: `← 로그인으로`.
- OTP 입력: 46px, 22px, 가운데, 자간 8px, maxlength 6.
- 오류는 카드 안 빨간 줄(높이 유지). 가입 성공 시 로그인으로 돌아가 토스트 `가입 신청 완료. 관리자 승인 후 로그인할 수 있습니다.`
- 가입 폼 8칸 2열: 성, 이름, 생년월일, 전화번호, 이메일, 아이디, 비밀번호, 비밀번호 확인.
- 1000px 이하: 소개 숨김, 카드 가운데, 전체에 옅은 어둠.
- 데모 계정 안내는 표시하지 않는다.

## 수용 기준

AUTH-T01 승인 사용자 로그인. T02 대기·반려·중지 안내. T03 OTP 계정은 1차 인증만으로 보호 API 불가. T04 중복·형식·확인 불일치 거절. T05 가입 후 pending, 로그인 불가. T06 로그아웃·만료 후 401. T07 접근 로그가 계정과 일치.
