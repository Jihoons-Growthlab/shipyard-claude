# SWP Shipyard Rebuild

조선소 통합관리 시스템을 `specs/`만으로 새로 구현한다. Stack: FastAPI, Vue 3, SQLite, Unity Web.
시작 경로는 `specs/index.md`, 진행 상태는 `PROGRESS.md`다.

## 원칙

- 기능과 화면은 명세와 `reference/ui/` 기준으로 유지하고, 내부 코드는 중복 없이 새로 설계한다.
- 검증·권한·업무 규칙은 백엔드가 소유한다. 화면의 비활성화는 편의일 뿐이다.
- 공통 규칙은 한 곳에 구현하고 재사용한다. 요청되지 않은 기능을 추가하지 않는다.
- 명세에 없는 값이나 동작을 지어내지 말고, 미확정 사항은 `specs/index.md` 기준을 따른다.
- 실행하지 않은 테스트나 보지 않은 화면을 완료로 보고하지 않는다.

## 읽기

- 현재 단계의 명세와 그 단계에 필요한 이미지만 연다. 전체 명세·이미지를 한 번에 읽지 않는다.
- 파일을 통째로 출력하지 말고 검색 후 필요한 구간만 읽는다. 긴 로그는 오류 구간만 본다.
- `reference/seed/seed.json`은 코드로 적재한다. 구조는 앞부분만 확인한다.
- `.gitignore` 대상(의존성, 빌드 결과, Unity 캐시, 로그, DB, `.playwright-mcp/`)은 기본 읽기·검색 대상이 아니다. 오류 추적에 필요하면 해당 파일의 해당 구간만 본다.
- 검색은 `backend/`, `frontend/src/`처럼 소스 폴더로 범위를 좁힌다.
- 토큰을 아끼려고 기능, 필요한 추론, 테스트, 화면 확인을 줄이지 않는다.

## Compact Instructions

대화를 압축할 때 요약에 다음을 남긴다.

- 전체 목표: `specs/`만으로 완성본과 같은 기능·화면을 새로 구현
- 사용자 제약: 이번 세션에서 사용자가 지시한 내용
- 현재 단계와 진행 기록 경로 `PROGRESS.md`
- 미해결 오류: 증상, 재현 명령, 관련 파일, 로그 경로
- 검증 상태: 통과, 실패, 미실행을 구분

완료된 단계의 세부 내용, 긴 로그, 해결된 시행착오는 요약하지 않는다.
