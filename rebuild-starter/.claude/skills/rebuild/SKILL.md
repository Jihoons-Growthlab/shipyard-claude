# /rebuild

단계 목록은 `specs/index.md`에 있다. 끝날 때까지 아래를 반복한다.

1. **확인**: `PROGRESS.md`를 읽는다(없으면 만든다). 환경 점검 기록이 없으면 `specs/index.md`대로 수행한다. 완료 단계는 다시 분석하지 않는다.
2. **읽기**: 첫 미완료 단계의 명세와 그 단계의 이미지만 연다. 이전 단계 자료는 필요한 구간만 다시 연다.
3. **구현**: 이미 만든 코드를 검색해 재사용하며 구현한다.
4. **검증**: 관련 테스트를 실행하고, 화면이 있는 단계는 앱을 실행해 Playwright로 이미지와 비교한다.
5. **기록**: 단계가 끝나거나 막힐 때 `PROGRESS.md`를 갱신한다. 매 응답마다 갱신하지 않는다.
6. **계속**: 다음 단계로 넘어간다.

단계 완료는 해당 명세의 수용 기준, 관련 테스트, 화면 확인을 모두 충족한 상태다.

## PROGRESS.md

유일한 진행 기록이다. 40줄 이내로 유지하고 누적하지 말고 덮어쓴다. 맨 위의 실험 기록과 환경 점검 결과는 유지한다.

```markdown
- 현재 단계: 5/12 공정 계획 (완료: 1~4)
- 완료 기준: 충족 항목 수 / 미충족 항목
- 핵심 결정: 다음 단계에 영향을 주는 것만
- 변경 파일: 현재 단계의 폴더 또는 파일
- 실패한 검증: 항목과 로그 경로. 해결되면 지운다
- 다음 작업: 바로 이어서 할 일
```

긴 로그와 과거 시행착오는 적지 않는다. 다시 볼 출력은 `logs/<단계>-<내용>.log`에 저장하고 경로만 적는다.

## 세션

- 압축은 자동 압축에 맡기고, `/clear`는 실행하지 않는다.
- 압축이나 새 세션 뒤 세부가 불확실하면 추측하지 말고 `PROGRESS.md`와 현재 단계 명세를 다시 읽는다.

## 멈추는 경우

설치·라이선스·로그인처럼 사용자만 할 수 있는 조치가 필요할 때만 멈춘다. 그때 정확한 조치를 알리고 `PROGRESS.md`에 기록한다. Unity 단계만 막혔다면 다른 단계를 먼저 끝낸다.

마지막 단계까지 끝나면 통과한 검증과 미확인 항목을 구분해 보고한다.
